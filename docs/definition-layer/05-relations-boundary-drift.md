# 05. 对象关系、版本边界与漂移检查

## 1. 建议的对象关系

定义层对象的依赖关系建议如下：

```text
generator -> context -> template -> machine -> instance_group -> scenario
```

同时：

* `system` 作为命名空间与组织边界贯穿其中。
* `time_profile` 由 `scenario` 引用。
* 攻击分支是 `machine` 的内部语义，不改变对象依赖方向。
* 不新增 `attack_chain` 依赖节点。

## 2. 依赖方向说明

* `context` 可引用 `generator`。
* `template` 可引用 `context`。
* `machine` 可引用 `template`。
* `instance_group` 可引用 `machine`。
* `scenario` 组合多个 `instance_group`。

反向依赖应尽量禁止，以防结构纠缠。

## 3. 当前版本支持

当前版本支持：

1. 单系统单实例。
2. 单系统多实例。
3. 多系统并行场景。
4. 全局 / 系统 / 实例 / 事件四层作用域。
5. 状态机定义。
6. 模板定义。
7. 生成器契约引用。
8. 时间基础约束。
9. 多实例复用同一行为模型。
10. 单 `machine` 内攻击分支。
11. 基于状态类别的攻击标签。
12. 基于转移权重的攻击路径采样。
13. 攻击状态多事件发射。

## 4. 当前版本不支持

当前版本不支持：

1. `entity`。
2. 弱因果。
3. 强因果 DAG。
4. 跨实例依赖建模。
5. 跨系统依赖建模。
6. 动态图修改。
7. 任意脚本执行。
8. 跨 `machine` 攻击链。
9. 顶层 `attack_chain`。
10. 基于 `instance_group.attack_ratio` 的攻击配额控制。
11. 攻击阶段对象。
12. 事件级 DAG。

## 5. 设计态度

当前版本不是“功能不够全”，而是主动收敛。

目标是优先建立一个清晰、稳定、可执行的定义层框架。未来如果需要跨系统攻击链，应以明确新增模型的方式引入，而不是在当前模型上偷偷叠补丁。

## 6. 漂移检查清单

实现和扩展过程中，应定期检查以下问题。

### 6.1 行为模型是否漂移

* `machine` 是否仍只描述状态、转移、终止和事件发射？
* 是否有人把执行逻辑塞回了定义层？
* 是否有人把跨 `machine` 依赖塞进了 `machine`？

### 6.2 模板是否漂移

* `template` 是否仍只做字段绑定？
* 是否开始混入复杂脚本和共享逻辑？
* 是否有人在 `template` 中固化攻击语义？

### 6.3 作用域是否漂移

* 变量共享是否仍由 `context` 管理？
* 是否有人在模板里临时发明作用域？
* 是否有人为第一版攻击变量引入跨实例身份图？

### 6.4 多实例是否漂移

* 多实例是否仍通过 `instance_group` 建模？
* 是否有人开始复制多份 `machine` 代替实例化？
* 是否有人在 `instance_group` 中增加第二套攻击比例控制？

### 6.5 多系统是否漂移

* 多系统是否仍只是共享全局上下文的并行系统？
* 是否有人偷偷引入依赖关系而没有升级模型？
* 是否有人通过多系统引用绕出跨系统攻击链？

### 6.6 攻击建模是否漂移

* 攻击是否仍只存在于单个 `machine` 内？
* 是否有人新增了顶层 `attack_chain`？
* 是否有人通过 `scenario` 偷偷实现攻击链编排？
* 是否有人把 `transition.weight` 当成全局攻击比例硬约束？
* 是否有人引入攻击阶段 `stage` 或事件级 DAG？

### 6.7 CUE 使用方式是否漂移

* CUE 是否仍主要用于结构、约束、组合与校验？
* 是否开始承担执行期逻辑？
* 是否有人把 CUE 写成了披着配置皮的脚本？

只要这些问题里有几项开始模糊，设计就已经在跑偏。

## 7. 后续扩展方向

以下能力作为未来版本候选，但不进入当前版本。

### 7.1 `entity`

用于支持跨实例、跨系统的稳定对象身份。

### 7.2 causal DAG

用于支持复杂攻击链、跨系统因果依赖与传播。

### 7.3 richer interaction model

用于支持实例之间显式交互与依赖。

### 7.4 attack chain model

用于未来支持跨 `machine`、跨 `system` 的攻击链。

如果未来真的需要攻击链，就新增清晰模型，不要把 `scenario`、`instance_group`、`template` 改造成地下攻击链。那种补丁设计像在自行车上焊火箭，能跑，但通常先炸。

## 8. 最终结论

当前版本定义层坚持以下框架：

* 用 `machine` 定义行为图。
* 用 `template` 定义事件结构。
* 用 `generator` 定义值来源契约。
* 用 `context` 定义变量与作用域。
* 用 `instance_group` 定义多实例。
* 用 `scenario` 定义总体场景。
* 用 `time_profile` 定义基础时间约束。
* 用 `system` 划分系统边界。

同时明确：

* 当前版本保留 `instance`。
* 当前版本不引入 `entity`。
* 当前版本不支持弱因果。
* 当前版本不支持因果 DAG。
* 当前版本不支持跨 `machine` 攻击链。
* 当前版本不引入 `attack_chain`。

一句话概括：

> 当前版本的定义层，目标不是描述一切可能的关系，而是稳定地描述行为模型、事件模板、共享变量、多实例、多系统并行场景，以及单 `machine` 内的最小攻击分支。
