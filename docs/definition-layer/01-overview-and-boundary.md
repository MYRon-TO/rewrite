# 01. 总览与边界

## 1. 定义层职责

定义层负责声明结构、约束、引用关系与复用方式，核心回答四个问题：

1. 行为如何演化：由 `machine` 定义状态、转移、终止条件和状态关联事件。
2. 事件如何生成：由 `template` 定义日志模板、字段结构和字段绑定方式。
3. 值从哪里来、在哪共享：由 `generator` 和 `context` 定义值来源、变量作用域和复用边界。
4. 一次仿真要跑多少实例、哪些系统：由 `scenario` 和 `instance_group` 定义启用系统、实例数量和共享配置。

## 2. 定义层不负责

定义层不负责执行逻辑，包括：

* 状态转移采样算法。
* 运行时缓存实现。
* 时间推进实现。
* 数据扰动实现。
* Hook 执行机制。
* 攻击控制器实现。
* 输出渲染与导出。
* 文件拼接、混流与排序。

定义层只描述“是什么”，不描述“怎么做”。

## 3. 设计原则

### 3.1 声明式优先

定义层只声明模型，不嵌入执行代码。

### 3.2 图优先，不用矩阵

状态机采用“状态 + 局部转移”表达，不要求用户直接书写概率矩阵。

### 3.3 共享逻辑属于上下文层

变量共享由 `context` 定义，不由 `template` 临时发明。

### 3.4 生成与复用分离

“生成一个值”和“在某个作用域内复用这个值”必须拆开表达。

### 3.5 多实例是一等公民

同一行为模型应支持被批量实例化，而不是复制多份定义。

### 3.6 第一版刻意收缩

当前版本优先保证模型清晰、边界稳定、可实现、可验证，不追求覆盖所有复杂攻击链和跨系统因果关系。

## 4. 当前版本支持的场景

当前版本重点支持：

1. 单系统单实例。
2. 单系统多实例，例如多个用户独立执行同一个登录流程。
3. 多系统并行生成，各系统共享全局上下文，但不建立跨系统依赖图。
4. 单 `machine` 内的攻击分支，攻击行为表现为攻击状态和攻击转移路径。

## 5. 当前版本不支持的场景

当前版本明确不支持：

1. `entity` 独立建模。
2. 跨实例稳定身份图。
3. 弱因果触发机制。
4. 强因果 DAG / 跨系统依赖编排。
5. 顶层 `attack_chain`。
6. 跨 `machine` 攻击链。
7. 攻击阶段 `stage`。
8. 事件级 DAG。
9. 脚本式攻击编排。
10. 通过 `instance_group.attack_ratio` 控制攻击比例。

## 6. 多实例边界

多实例不是“多个模型相互作用”，而是：

> 同一个模型的多份独立运行。

支持：

* 同一个 `machine` 被多个实例重复运行。
* 实例彼此独立。
* 实例共享 `global` 和 `system` 级变量。
* 实例拥有各自独立的 `instance` 级状态和变量。

不支持：

* 实例之间互相调用、互相触发。
* 实例之间显式消息传递。
* 实例间复杂依赖或同步机制。

## 7. 多系统边界

多系统只是：

> 多个系统并行参与同一个场景，并共享部分全局上下文。

支持：

* 一个 `scenario` 同时包含多个 `system`。
* 不同 `system` 共享 `global` 上下文。
* 各系统拥有各自的 `system` 级变量。
* 各系统绑定各自的 `machine` 和 `template`。

不支持：

* 跨系统因果链。
* 跨系统触发器。
* 弱因果机制。
* 因果 DAG。
* 跨系统事件依赖编排。
